# podlet-provider

A community OpenTofu and Terraform provider for managing rootless Podman Quadlet
resources on remote machines.

## Features

- One SSH target per provider instance, with aliases for multiple machines.
- Strict SSH host-key verification by default.
- SSH agent and unencrypted private-key authentication.
- Typed, Kubernetes-inspired `metadata` and `spec` blocks.
- Container, network, and volume Quadlet resources.
- Atomic remote file replacement and provider ownership protection.
- User systemd reload, enable, restart, status, and deletion handling.
- Remote drift refresh and import of provider-managed Quadlet files.

The target user must already have Podman, Quadlet, and a working user systemd
session. This provider does not provision the machine or install Podman.

## Usage

```hcl
terraform {
  required_providers {
    podlet = {
      source = "registry.terraform.io/xiantongc612/podlet"
    }
  }
}

provider "podlet" {
  host             = "edge-1.example.com"
  user             = "containers"
  private_key_path = "~/.ssh/id_ed25519"
  known_hosts_path = "~/.ssh/known_hosts"
}

resource "podlet_network" "service" {
  metadata {
    name = "service"
  }

  spec {
    driver = "bridge"
  }
}

resource "podlet_volume" "data" {
  metadata {
    name = "service-data"
  }

  spec {
    driver = "local"
  }
}

resource "podlet_container" "service" {
  metadata {
    name        = "service"
    description = "Example HTTP service"
  }

  spec {
    image = "docker.io/library/nginx:1.29"

    port {
      host_port      = 8080
      container_port = 80
      protocol       = "tcp"
    }

    mount {
      source = podlet_volume.data.reference
      target = "/usr/share/nginx/html"
    }

    networks = [podlet_network.service.reference]

    service {
      restart = "on-failure"
    }
  }
}
```

See [`examples`](examples) and the generated [`docs`](docs) for the complete
schema.

## Lifecycle And Drift

The provider writes rootless Quadlets to `.config/containers/systemd` relative
to the SSH user's home by default. It then invokes `systemctl --user` to reload
systemd and manage generated units.

Generated files contain an ownership marker. Creation and deletion refuse to
replace an unmarked file at the managed path. During refresh, supported values
are parsed from the remote file into state, so the next plan reconciles manual
changes back to configuration. Removing a remote file removes the resource from
state so it can be recreated.

Resources can be imported on the host configured by their provider instance:

```shell
tofu import podlet_container.service container/service
tofu import podlet_network.service network/service
tofu import podlet_volume.data volume/service-data
```

Only files previously generated by this provider can be imported.

## Authentication

SSH agent authentication is enabled by default when `SSH_AUTH_SOCK` is set. An
unencrypted key can be selected with `private_key_path`; both methods may be
enabled together. Host keys are checked against `~/.ssh/known_hosts` unless
`known_hosts_path` is set explicitly.

`insecure_ignore_host_key = true` is available for disposable environments but
should not be used in production.

Values in `spec.environment` are marked sensitive in CLI output, but OpenTofu
still stores them in state. Prefer a remote `environment_files` entry or a
separate secret-delivery mechanism for credentials.

## Development

Install [Devbox](https://www.jetify.com/devbox/docs/installing_devbox/), then run:

```shell
devbox run init
devbox run check
```

Useful focused commands are `devbox run fmt`, `devbox run lint`, `devbox run
test`, `devbox run build`, and `devbox run docs`.

To use a local build, create an OpenTofu CLI configuration with a
`dev_overrides` entry pointing at the directory containing
`terraform-provider-podlet`:

```hcl
provider_installation {
  dev_overrides {
    "registry.terraform.io/xiantongc612/podlet" = "/absolute/path/to/build"
  }
  direct {}
}
```

Then set `TF_CLI_CONFIG_FILE` to that file when running OpenTofu. The opt-in
`devbox run integration` command requires `PODLET_TEST_HOST`, `PODLET_TEST_USER`,
and optionally SSH path and port environment variables for a prepared rootless
Podman host.

## Limitations

- The initial release supports rootless Podman only; dual-mode rootless/rootful support with both root SSH login and NOPASSWD sudo is planned.
- Password authentication, encrypted private keys, and jump hosts are not yet
  supported.
- Pod, image, build, kube, and artifact Quadlets are not yet modeled.
- The parser manages directives exposed by the typed schema. Unsupported manual
  directives are not preserved when configuration is reconciled.
